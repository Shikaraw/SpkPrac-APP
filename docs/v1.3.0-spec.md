## 一、Android 前台服务（android-infra）

### 1.1 类与契约

新建 `app/src/main/java/com/spkprac/app/service/PracticeService.kt`，
类名必须是 `com.spkprac.app.service.PracticeService`（清单已按此声明，`foregroundServiceType=microphone`）。

```kotlin
companion object {
    const val ACTION_START = "com.spkprac.app.action.PRACTICE_START"
    const val ACTION_STOP  = "com.spkprac.app.action.PRACTICE_STOP"
    const val EXTRA_MODE   = "mode"        // 已经本地化的显示名，如 "口语练习" / "自由对话"
    const val EXTRA_STARTED_AT = "startedAt" // System.currentTimeMillis()

    fun start(context: Context, modeLabel: String, startedAt: Long)
    fun stop(context: Context)
}
```

### 1.2 行为

- `ACTION_START`：`startForeground()` **必须在 5 秒内调用**，否则 ANR。
- 通知渠道：id `practice`，名称/描述走字符串资源，`IMPORTANCE_LOW`，无声、不亮灯。
- 通知内容：
  - 标题：`练习中`
  - 正文：`{modeLabel}`（例如 "口语练习"）
  - **计时用系统计时器**：`setWhen(startedAt).setUsesChronometer(true).setShowWhen(true)`，
    这样不需要每秒刷新通知，省电且准确。
  - `setOngoing(true)`、`setOnlyAlertOnce(true)`、`setCategory(CATEGORY_SERVICE)`、
    `setPriority(PRIORITY_LOW)`、`setSilent(true)`
  - 小图标用已有的通知/应用图标（`R.drawable.ic_stat_practice` 或复用现有 drawable，不要用 mipmap 大图）
- 点击通知：`PendingIntent` 打开 `MainActivity`（`singleTask` 会复用现有任务栈），
  `FLAG_IMMUTABLE`，action 用 `Intent.ACTION_MAIN` + `CATEGORY_LAUNCHER` 语义正确。
- `ACTION_STOP`：`stopForeground(STOP_FOREGROUND_REMOVE)` + `stopSelf()`。
- `onDestroy` 里确保 `stopForeground`。
- `START_NOT_STICKY`（进程被杀不自动重启，避免出现没有会话的幽灵通知）。

### 1.3 接入点

在 `core/SessionViewModel.kt` 里：
- 会话真正建立（拿到 `session.updated` / 状态变为已连接）后 `PracticeService.start(...)`；
  **不要**在用户还没连上时就弹通知。
- 会话结束/失败/`onCleared()` 时 `PracticeService.stop(...)`，必须幂等（重复 stop 不报错）。
- ViewModel 需要 `Context`：用 `AndroidViewModel` 或通过 `getApplication()` 已存在的方式拿；
  **不要**为拿 Context 改架构，若 ViewModel 目前不是 AndroidViewModel，就在构造处传 `Application`。

### 1.4 通知权限

`POST_NOTIFICATIONS`（Android 13+）必须在 `MainActivity` 里运行时申请一次：
- 用 `ActivityResultContracts.RequestPermission()`，在**首次进入会话页时**申请（不要一启动就弹）。
- 用户拒绝也要能正常练习（服务照常跑，只是没有通知），不得阻塞流程。
- `FOREGROUND_SERVICE_MICROPHONE` 需要 `RECORD_AUDIO` 已授予——它本来就已申请，保持顺序即可。

### 1.5 验收

- 进入会话 → 通知栏出现"练习中"，带计时；退出到桌面/锁屏 → 通知仍在，计时继续。
- 结束会话 → 通知消失。
- 反复进入退出 10 次 → 不残留通知、不崩溃。

## 二、修复 Android 更新检查（android-infra）

### 2.1 问题

`UpdateChecker.kt` 用 `/releases/latest`。仓库同时发布 Windows 版（tag 前缀 `pc-v`），
GitHub 的 "latest" 按发布时间选，**当前返回的是 `pc-v1.2.0`，导致安卓端误判为"已是最新"。**

### 2.2 修法

- 请求改为 `GET {base}/repos/{owner}/{repo}/releases?per_page=30`（数组）。
- 过滤条件（顺序取第一个命中的）：
  1. `draft == false`
  2. `tag_name` 以 `v` 开头（大小写敏感）
  3. **排除** `tag_name` 以 `pc-v` 开头（`v` 开头且不是 `pc-v`，注意 `pc-v` 本身不以 `v` 开头，但仍显式排除以防万一）
  4. 能解析出形如 `x.y.z` 的版本号
- 一个都没有 → 视为"已是最新"（`available=false`），不要报错。
- 其余逻辑（镜像回退、APK asset 选择、版本比较、下载）保持不变。
- 版本号解析要健壮：`tag.removePrefix("v")` 后再交给现有 `compare`；对于 `pc-v...` 之类已过滤，不需要额外兼容。

### 2.3 验收

- 用一个**临时**单测或可执行的 Kotlin 脚本验证过滤逻辑（不能联网也没关系）：
  给定一个包含 `v1.2.0`、`v1.1.0`、`pc-v1.2.0`、`pc-v1.0.0` 的假数组，必须选中 `v1.2.0`。
- 若不方便加测试，至少把过滤逻辑抽成 `internal fun pickLatestRelease(json: JsonArray): JsonObject?`
  纯函数并在报告里贴出它的输入输出推理。

## 三、搜索历史对话内容（android-infra 提供 API，android-ui 用）

### 3.1 `SessionRepo` 新增

```kotlin
/** 返回 sessionId -> 命中片段（≤ 80 字，前后各留一点上下文）。大小写不敏感，搜 user+assistant 两侧文本。 */
suspend fun searchContent(query: String): Map<String, String>
```

- 空 query 直接返回空 map。
- 只在 IO 线程读文件；单个会话文件损坏要跳过，不能整体失败。
- 片段里命中处用 `…` 包住上下文即可，**不要**返回带标记的高亮文本（交给 UI 决定）。

### 3.2 首页搜索（android-ui）

- 过滤条件 = 标题命中 **或** 语言名命中 **或** `searchContent` 命中。
- 内容命中时，在会话行下方显示一行灰色片段文本（单行、`maxLines=1`、`TextOverflow.Ellipsis`）。
- 输入防抖 150–250ms（用 `snapshotFlow` + `debounce` 或 `LaunchedEffect` + `delay`），
  避免每敲一个字符就读一遍全部会话文件。
- 搜索中可显示一个小的 loading，不要卡住主线程。

## 四、Android 无障碍（android-ui）

逐屏检查（Home / PracticeSetup / Session / SessionDetail / Settings / VoiceManager / VoiceDetail）：

1. **所有仅图标的可点击控件必须有 `contentDescription`**，用字符串资源，不要硬编码中文。
   纯装饰图标传 `null`。
2. **触控目标 ≥ 48dp**：小图标按钮加 `Modifier.minimumInteractiveComponentSize()` 或显式尺寸。
3. **标题层级**：页面大标题、区块标题加 `Modifier.semantics { heading() }`。
4. **状态变化要播报**：
   - 会话状态胶囊（连接中/已连接/思考中/说话中）加 `liveRegion = LiveRegionMode.Polite` + `stateDescription`
   - 错误横幅同上
   - 新消息进入对话记录时可给容器 `liveRegion = Polite`（注意别刷屏，只对最新一条）
5. **自绘元素**：`VoiceOrb`、音量波形等 Canvas 加 `contentDescription` 描述当前状态
   （如"语音球：正在聆听"），否则 TalkBack 读不到。
6. **滑块**（灵敏度/静音时长/麦克风增益）加 `stateDescription` 报告当前值。
7. **自定义 `Modifier.pressable`** 必须补 `semantics { role = Role.Button; onClick { ...; true } }`。
8. 不要破坏现有视觉与布局；无障碍改动以"加语义/加描述/调尺寸"为主，**不重排 UI**。

## 五、选中文本 → 翻译 / 问 AI（android-ui + pc-feature）

### 5.1 共同交互

用户选中词或一段文本 → 出现菜单，两项：

- **翻译**：把选中文本翻译成界面语言。
- **问 AI**：把选中文本发给已配置的文本模型，让它解释/举例，结果在弹窗里展示，可复制。

前提：文本模型已配置（endpoint + key + model）。未配置时提示"请先在设置里配置文本模型"。
无有效选中文本时不显示菜单。

### 5.2 Android

- 新建 `ui/components/SelectableText.kt`：用 `AndroidView(TextView)` 包装，
  `setTextIsSelectable(true)`，通过 `customSelectionActionModeCallback`
  **在系统文本选择菜单里追加两项**（`ActionMode.Callback` 的 `onPrepareActionMode` 里
  用 `menu.add(...)` 并 `menuItem.setShowAsAction(SHOW_AS_ACTION_IF_ROOM)`）。
  回调里通过 `textView.selectionStart/End` 取真实选中文本。
- TextView 的字体/颜色/行高要跟随 Compose 主题（`MaterialTheme.typography` + `colorScheme`），
  视觉上要和现在的文本框看不出差别。
- 「翻译」：
  - 优先 `Intent(ACTION_PROCESS_TEXT)`（`type = "text/plain"`，`EXTRA_PROCESS_TEXT` = 选中文本，
    `EXTRA_PROCESS_TEXT_READONLY = true`），让系统翻译类应用接管；
  - `resolveActivity == null` 时**回退**调用文本模型翻译，并在同一个结果弹窗展示。
- 「问 AI」：打开结果弹窗（loading → 结果 → 复制/关闭），走现有 `TextApi`。
- 应用范围：会话页的气泡、会话详情页的气泡（这两处最常需要查词）。别的长文本可选。

### 5.3 PC

- 在会话页 / 详情页的对话区域，监听 `selectionchange` + `mouseup`：
  若 `window.getSelection()` 非空且锚点位于 `#session-root` 或详情页对话容器内，
  在选区右上方浮出一个小工具条（复用现有 `.btn` 样式、深色玻璃质感），两个按钮：翻译 / 问 AI。
- 翻译：调用 `SP.api.complete`，提示词要求"只输出译文"；结果用小气泡展示在工具条下方。
- 问 AI：弹出对话框（复用 `SP.ui.openDialog`），loading → 结果（`SP.markdown.render`）→ 复制/关闭。
- 关闭时机：点击别处、滚动、按 Esc、选区清空。
- 不要和现有的长按/右键菜单冲突。
